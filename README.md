# recommend-book

世界の小説を整理し、読書履歴や好みに合う作品を推薦するためのデータ基盤です。古典から現代小説・ライトノベルまでを対象に、まず1,000〜3,000作品で試作し、将来は10万作品以上への拡張を目指します。

## できること

- Open Library・国立国会図書館・Wikidataなどの書誌情報を取り込み、作品・翻訳・刊行版を区別して管理します。
- LLMでジャンル、テーマ、物語構造、主人公、文体、雰囲気を分類し、判定の根拠と信頼度を保存します。根拠が足りない項目は「不明」として扱います。
- 読書履歴を使って候補に順位を付け、推薦理由を表示します。既読と確認できた作品は除外します。
- データごとの利用条件を記録し、AI入力・表示・再配布などに使える範囲を管理します。

分類精度・信頼度の校正・本人向け推薦の改善は、まだ検証できていません。翻訳や版の対応も一部に限られます。読書状態が不明な作品を「未読」とは扱いません。商用利用は資料や用途ごとに確認が必要です。

件数、実際のモデル実行、撤回・復旧、画面確認の範囲は[実生成・検証報告](docs/autonomous-next-delivery-report-v3.md)にまとめています。自動テストと実データでの確認は区別して記録します。

## 開発・ローカルでの確認

Python 3.12以上と[uv](https://docs.astral.sh/uv/)を使用します。

```powershell
uv sync --locked
uv run recommend-book --help
uv run pytest -q
```

取得データ・DB・評価資料は`data/`にローカル保存しており、Gitには含めていません。リポジトリを取得するだけでは推薦用データは揃いません。

生成済みデータがある環境では、次のファイルをブラウザで開くと推薦画面を確認できます。

```text
data/autonomous-next-v3/database/phase7-world-pilot-delivery-v1/index.html
```

## 次に進めること

新規36小説の入力と新しい処理版を固定し、最初の10作品の分類・審査・DB採用・表示まで実行しました。推薦特徴を採用できたのは4作品で、採用率40%は目標70%を下回ります。残り26作品の分類は開始していません。

1. 今回の保留理由をもとに、あらすじで判断できる分類範囲と採用方針を改善する。
2. 新しい根拠や処理版が整った対象だけ小バッチで検証し、採用率・保留率・時間・利用量を確認する。同じ入力の分類を繰り返さない。
3. 用途確認済みの候補と処理枠を確保し、条件を満たしてから1万→3万→10万作品へ進む。現在、1万作品の一括処理は開始しない。

保留済みの対象は、新しい根拠が得られた場合だけ再開する。本人履歴への内容接続が増えた場合だけ推薦を再比較する。

前回は合成データで旧分類の失効・中断再開・撤回後のHTML更新を検証し、既存335評点の評価を整理しました。[更新検証](docs/content-update-verification-v1.md)、[推薦の現在評価](docs/personal-recommendation-current-assessment-v1.md)、[診断準備](docs/codex-diagnostic-preparation-v1.md)に結果と限界を記録しています。

続く[20作品・名寄せ3組の照合](docs/bounded-scope-repair-v1.md)では、採用できる修正は0で保留を維持しました。[履歴側1作品の追加確認](docs/personal-content-pilot-v1.md)もシリーズと原連載の対応が未解決で、新規接続は0です。[拡張条件の実測](docs/scaling-readiness-v1.md)により、現時点で1万作品の一括処理は開始しない判断としました。

その後、確認できた品質の範囲と処理量を見ながら1万→3万→10万作品へ拡張します。

追加の試読・採点・正解データ作成を利用者へ依頼しない方針です。

追加費用をかけず、既存データ・利用条件を満たす無料公開資料・Codexだけで進めます。外部委託やデータ購入は行いません。Codexによる評価と、独立した人手による精度検証は区別します。
