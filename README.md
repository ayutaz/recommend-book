# recommend-book

世界の小説を整理し、読書履歴や好みに合う作品を推薦するためのデータ基盤です。古典から現代小説・ライトノベルまでを対象に、まず1,000〜3,000作品で試作し、将来は10万作品以上への拡張を目指します。

## できること

- Open Library・国立国会図書館・Wikidataなどの書誌情報を取り込み、作品・翻訳・刊行版を区別して管理します。
- LLMでジャンル、テーマ、物語構造、主人公、文体、雰囲気を分類し、判定の根拠と信頼度を保存します。根拠が足りない項目は「不明」として扱います。
- 読書履歴を使って候補に順位を付け、推薦理由を表示します。既読と確認できた作品は除外します。
- データごとの利用条件を記録し、AI入力・表示・再配布などに使える範囲を管理します。

## 開発・ローカルでの確認

Python 3.12以上と[uv](https://docs.astral.sh/uv/)を使用します。

```powershell
uv sync --locked
uv run recommend-book --help
uv run pytest -q
```

取得データ・DB・評価資料は`data/`にローカル保存しており、Gitには含めていません。リポジトリを取得するだけでは推薦用データは揃いません。

生成済みデータがある環境では、次のファイルをブラウザで開くと推薦画面を確認できます。

```text
data/autonomous-next-v3/database/phase12-world-delivery-v1/index.html
```

## 次に進めること

1. 保留の理由を解消できる新しい根拠がある作品だけ処理する。今回残った5作品は、引用または著者名の対応不足で保留しています。
2. 履歴接続が増えた場合だけ推薦を再比較し、分類定義と利用条件が合う独立資料で評価する。同じ資料の再取得・同じ入力の再分類・件数合わせの探索は繰り返しません。
3. 品質・対象構成・採用率・処理量・無料利用枠を確認してから1万→3万→10万作品へ進む。少数の英語ミステリー5作品の成功だけでは大量処理を開始しません。

追加の試読・採点・正解データ作成を利用者へ依頼しない方針です。

追加費用をかけず、既存データ・利用条件を満たす無料公開資料・Codexだけで進めます。外部委託やデータ購入は行いません。Codexによる評価と、独立した人手による精度検証は区別します。
