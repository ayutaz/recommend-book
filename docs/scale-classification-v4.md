## ここからの順序

### 1. 最初の投入は成立。取得済み資料から後続入力を供給する

最初の6区間で、選択515作品から510作品を分類・別審査・用途確認後にDBへ採用した。分類の失敗3作品、分類後の用途確認による未採用2作品、表示特徴482作品、内容根拠付き非ジャンル特徴445作品で、各区間の継続条件を満たした。後続96作品の工程が始まっている。入力の準備件数は分類完了数へ加算しない。

並行して、後続の保存資料と不足する内容資料を準備する。既存の保存資料・取得キャッシュを使い、無料で条件を満たす取得経路から、実行できる単位で受け渡す。1万作品分の資料がすべて揃うまで最初の分類を待たせない。

### 2. 新規1万作品を追加し、詳細分類を累計2万作品にする

確認時点の10,510作品から残り9,490作品を、同じ工程で差分追加する。Sol CLIは既存の4〜8並列制御・最大8並列を使う。既存1万作品の再分類と、失敗した同一入力の自動再送は行わない。用途確認を通過した新規資料だけを処理し、採用分から順次推薦に反映する。

内容資料の取得、分類入力の準備、分類を並行する。書誌ジャンル不明作品の最初の83作品は4並列で処理し、分類82作品・DB採用81作品・表示特徴71作品・内容根拠付き非ジャンル特徴65作品となった。分類失敗1作品と用途確認による未採用1作品は保持し、再送しない。実際の分類・別審査・利用条件確認・DB反映を経てcontrollerはexit 0で終了し、後続へ移行した。書誌ジャンル不明と資料ジャンル推薦の対象外という元の書誌情報は変更せず、本文から採用した特徴を別に使う。後続は既存の4〜8並列制御を維持する。取得は必要な供給量まで区切り、2万分類への拡張に不要な一般書誌の追加収集は後回しにする。

失敗率5%以下・表示特徴の採用70%以上という既存条件を維持する。日本語、ミステリー、ファンタジー、ライトノベル、年代の不足を優先するが、実資料の在庫がある範囲とする。国・地域と根拠のない文体は推測で補わない。

**完了条件:** 既存10,000作品を保持し、新規採用10,000作品を加えた20,000作品が実DBにあること。資料不足で未達の場合は到達数と不足を記録し、達成とはしない。表示特徴・6軸の採用と保留・偏り・実時間・CLI報告の利用量を併記する。

### 3. 待ち時間と履歴管理を並行して仕上げる

重複JSON処理の削減と証跡照合の最大4並列化を実装した。同条件・分類10,000作品の実HTTP各1回では、約42.9秒から約22.4秒となり、推薦30件の公開レスポンス全体が一致した。JSON処理の削減だけの段階では改善を確認できず、その後の証跡照合の並列化を含めた測定である。関連56試験が通過し、内容の二重読取り・改竄検出・撤回検出と、リクエストをまたいだ検証の再利用禁止を維持する。全件の証跡照合や性能調査の反復で分類拡張を止めない。

読書状態の保存・再起動・JSON持ち出し・削除を仕上げる。削除と競合更新の試験には合成データを使い、本人の履歴は削除しない。今回の持ち出し・削除対象は読書状態であり、既存335評価やすべての設定ではない。

再起動は実際のサーバープロセスを終了して別プロセスで起動し、合成3件の状態とexportが一致することを確認した。実ブラウザーからの保存では、新しく作成されたJSONファイルを読み取り、スキーマ・チェックサム・実HTTPとの内容一致を確認した。この時点の実際の読書状態は0件であり、複数件の状態・削除・競合更新は合成データで検証している。

### 4. 差分評価と利用準備をまとめ、Gitへ反映する

新しく確実な作品対応が得られた既存評価だけを照合する。比較可能な母数が成立すれば、資料ジャンルだけの推薦と内容特徴を使った推薦を同条件で比較する。成立しなければ評価不能と記録し、追加の本人評価や有料の評価資料は求めない。

最終監査と既存評価との差分照合のコードを用意し、合成データの35試験が通過した。既存1万分類の保持、実際の分類・別審査・利用条件・DB反映との対応、6軸と内容根拠付き非ジャンル特徴を確認する。既存335評価は過去の保存ハッシュと一致することを確認済みで、元データを変更しない。実DBでの最終監査・差分評価は2万作品到達後に行う。

AI入力・表示・再配布・商用利用を別々に整理し、個人データの保存先、持ち出し・削除、無料運用範囲をToC候補へ反映する。一般公開・商用提供はこの段階の完了条件に含めない。

実装の区切りで関連試験とコミット・pushを行う。確定した実装でUbuntu・WindowsのPython 3.14 CIを実行し、対象commitと検証結果を確認してPRを反映する。今回の計画説明だけを理由に、分類・取得・全試験を再実行しない。

## その先

2万分類の完了後、実際に不足している言語・年代・ジャンルと、無料で投入できる資料数を基に、3万分類への差分拡張を決める。その後も同じ条件で、10万作品以上の台帳を横断して推薦できる作品を増やす。検索10万作品の到達と、全10万作品の詳細分類は別の目標として扱う。

追加費用0・外注なし・本人の追加作業0を維持する。通常の取得・実装・検証・Git操作はCodexが判断して進める。全体の完了時期は、最初の100作品の実時間と後続資料の供給量を確認してから更新する。

初回100作品の4並列処理は、native開始からDB採用まで約35.8分だった。CLI報告の分類・別審査の合計は入力3,244,599 tokens、出力194,663 tokens。cached inputとreasoning outputは各合計の部分集合である。これはAPI請求額や独立した分類精度の測定ではない。8並列での継続処理と新しい資料の供給実績を見て、全体の所要時間を更新する。

直近の94作品は8並列でDB採用まで約19.1分、続く書誌ジャンル不明83作品は4並列で約23.9分だった。それぞれ1区間の実測で、資料が異なるため並列数の性能比較ではない。残りの分類時間は今後の採用速度と資料供給に左右され、最終監査・CIの時間とは分けて扱う。
