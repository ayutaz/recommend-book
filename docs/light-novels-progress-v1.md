# 日本のライトノベル対応の進捗

確認日: 2026-10-25。 [実行計画v22](autonomous-next-phase-plan-v22.md)の1〜4を実施中。日本のライトノベルを必須対象として追加し、出版社・レーベルごとの収録漏れを補っている。1,000シリーズ到達だけでは「ほぼ網羅」と判定しない。

## 現在使える範囲

| 項目 | 確認済みの状態 |
|---|---|
| 検索できる日本のライトノベル | 1,951シリーズ、235件の各巻・単独作品、5,698件の版・書誌。異なる単位を合算して作品数とはしない |
| 内容資料に基づく詳細分類 | 139シリーズに表示可能な特徴を採用。非ジャンルの内容特徴は99シリーズ（完了区間003まで）ジャンルだけの分類と、テーマなどの非ジャンル特徴は別集計 |
| 魔法科高校の劣等生 | シリーズとして検索・詳細・好きな作品への指定・別シリーズの推薦を実HTTPとChromeで確認 |
| 収録巻の表示 | 魔法科本編の1〜32巻のNDL書誌を、著者典拠・巻表示・出版情報と照合してシリーズへ接続。各巻の原作品IDを捏造しない |
| 既存の世界小説 | 別DBの検索・推薦を併用。既存2万作品の分類と、新しいシリーズ分類の件数は分けて保持 |

検索の「対象」で「日本のライトノベル」、「種別」で「シリーズ」を選べる。作品名・別題・著者で検索でき、好きなシリーズを指定して推薦を受け取れる。資料のジャンルだけで似た候補と、内容特徴を使った候補では根拠を区別する。シリーズ、各巻、版の読書状態は別に管理し、不明を未読に変換しない。

分類は既存のSol CLIで1シリーズずつ実施し、別呼出しで最大5シリーズを審査する。最初の2シリーズに続く67シリーズでは、50シリーズに内容根拠付き特徴を採用した（74.63%、分類処理失敗0、保留17）。Windowsのパス表記差による検証エラーは、元の入出力・hashを保った別検証記録で解消し、同じ分類を再送していない。採用率は独立した分類精度や推薦満足度ではない。根拠のない文体は不明のままとする。

次の65シリーズでは、出力の識別子不一致1件を保留した。途中停止前の有効な27結果を再利用し、未実行の37件だけを初めて分類して、成功64件を初めて別審査した。実試行65件の失敗率は1.54%、表示特徴は58件（89.23%）、内容根拠付きは55件である。書誌情報だけの3件を内容分類へ加算せず、内容特徴は累計107シリーズとなった。原記録を保持し、成功済み・失敗済みの分類の二重実行はしていない。

続く区間003の50シリーズでは、内容特徴32・表示特徴35を採用した。ここまでの実分類は184対象（有効183・失敗1）、別審査38呼出し、内容特徴139・非ジャンルの内容特徴99・書誌情報だけの表示6である。文体は有効183対象すべて不明である。CLIの観測利用量は入力・出力計5,690,929 tokensで、請求額を意味しない。以降の区間は分類と台帳への反映を継続中で、この確認時点の集計へ先取りして加えない。

## 収録漏れを減らす作業

Wikidataの取得済み候補1,806件を審査し、追加の明示資料による補完を含む1,511件を取り込んだ。日本語の題名だけでは採用せず、小説シリーズ・小説の種別を確認し、漫画・アニメを区別する。原言語が不明な項目を日本語と推定して埋めない。

Wikidataだけでは不足する。出版社公式の有限な一覧で、HJ文庫418、HJノベルス110、アリアンローズ114、SBクリエイティブのライトノベル一覧723の計1,365シリーズIDを取得した。既存台帳との題名等による照合候補は93件であり、題名一致だけを名寄せの確定としない。残る1,272件は未収録候補として照合を続ける。この1,365件は各一覧の対象範囲であり、日本全体の分母ではない。

著者情報まで再現できるHJ・アリアンローズの642シリーズをNDL書誌と照合し、244シリーズを新たに登録した。残る398件は既存Wikidata項目との重複が曖昧な39件と、必要な複合根拠が不足する359件に分けて保持している。新シリーズに535件の版を接続し、魔法科の32件を合わせて567件の所属を確認した。例えば「悪役令嬢後宮物語」はNDL由来のシリーズIDで検索できる。原言語は不明のまま保持し、明示された2〜8巻の版だけを所属させている。

その後、SBの公式シリーズ一覧とHJの別表記を加え、出版社一覧1,365件からNDL由来675シリーズを採用した。690件は潜在的な既存項目との重複92件と、書誌などの複合根拠不足598件に分けて保持している。Wikidata由来1,276シリーズと合わせて1,951シリーズであり、シリーズの名寄せ精度を独立評価した数値ではない。

公式資料で確認した75レーベルを対象に、NDL作成の書誌を直列取得している。NDL APIの取得窓に合わせて年・必要な場合は月で分割し、元資料・件数・識別子の重複とページ終端を保存する。出版社のシリーズIDとNDLの著者典拠・書名・出版情報が一致する場合は、Wikidata IDのないシリーズにも専用IDを付ける。書誌があることだけでラノベや原作品と確定しない。

取得制限の応答を受け、NDLへの間隔を20秒、制限後の待機を120秒に広げた。これは本プロジェクトの設定であり、提供元が定めた公式レートを意味しない。保存済みの途中経過から再開し、失敗履歴を残した限定的な回復で欠けを補う。75レーベルの取得は数時間単位で続き、取得中も検索・推薦・分類を利用できる。

要求数を減らすため、[NDL公式の全国書誌一括出力](https://www.ndl.go.jp/data/data_service/jnb)を追加確認した。正規の検索画面からDC-NDL形式で577件を一括取得し、全件のNDL由来主書誌を再現できた。従来の全蔵書検索と全国書誌では対象範囲が異なるため、新しい取得枠と原資料・条件記録を分けて取込みを準備している。提供元の制限を守り、第三者機関の書誌や紹介文を同じ許諾条件で扱わない。

出版社の一覧は発見・シリーズの存在確認に使い、画像・紹介文・本文を一括で再配布しない。書誌はNDL自身が作成した対象を選び、第三者提供の書誌へ同じ条件を広げない。AI入力・画面表示・再配布・商用利用の条件は資料と用途ごとに保存する。原資料・DB・個人履歴はGit対象外の`data/light-novels-v1/`等に置く。

## 残作業と完了条件

1. 取得中のレーベル別書誌と出版社シリーズ一覧を照合し、未収録・曖昧な対応・取得失敗を理由付きで解消または明示する。旧作・女性向け・Web発作品も対象に含める。
2. 固定20シリーズの検索・種別・対応を20/20で確認する。NDLだけにあるシリーズも含める。
3. 未処理の内容資料をSol CLIへ最大8並列で投入し、内容特徴あり500シリーズ以上を目指す。処理失敗率5%以下・表示採用率70%以上の条件を保ち、同じ失敗入力を繰り返さない。
4. 元の2万分類と履歴の保持、同一シリーズ・版の推薦重複や既読除外、用途条件と取得範囲を確認する。関連試験と確定した実装のUbuntu・Windows Python 3.14 CIを通し、結果文書・commit・push・PRへ反映する。

無料資料と既存のCodexだけを使い、購入・外注・本人による追加評価は求めない。各取得枠の完走と照合結果から収録範囲を報告し、日本全体の不明な分母に対する網羅率は作らない。独立した分類精度、確信度の校正、本人向け推薦の改善は引き続き未評価である。
