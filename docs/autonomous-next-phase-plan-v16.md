## 次に進めること

### 実行順と完了条件

現在は書名候補の処理を進めている。残る28関係から20関係を処理前に固定し、対象外の8関係は今回処理しない。修正中のコードや補完DBは、検証・公開表示の確認・Gitへの反映が終わるまで完了件数へ加算しない。

| 順序 | 作業 | 完了条件 |
|---|---|---|
| 1 | 固定した20書名関係を検証 | 元資料・言語・用途が成立する別題だけを検索へ反映し、取消と復元、変更外の不変を確認する |
| 2 | 保存負担と対象層を見直す | 固定資料の複製と作品ごとの増分を測定し、必要な共有化だけを実施する。言語・年代・ジャンルから次の不足層を決める |
| 3 | 新規候補だけを少量処理 | 最大20候補を固定し、成立分の最初の最大10作品を分類・審査する。実際の推薦表示と既読除外まで確認する |
| 4 | 拡張可否を再判定 | 改善後の処理時間・利用量・保存量と、未評価の品質を分けて報告し、次の対象と上限を決める |

各段階で成果を保存し、必要な検証後に自動でコミット・pushする。利用者への追加の判断・採点依頼を前提にしない。入力不足時は成立しなかった理由を保存し、同じ候補や終了済み調査を繰り返して件数を埋めない。

### 1. 未反映の書誌候補を整理する

今回保持した未反映28書名候補について、外国語の表示投影未対応27件と、既存ガードの選択条件に合わなかった日本語1件を分けて扱う。対応を広げる場合も正式な原題・訳題・表現・版の役割は別の根拠で確認する。タイトル・ISBNだけで統合せず、著者国籍で作品地域を代用しない。確認対象は最大20関係とし、旧DB全量コピー・hash・診断済み重複の再検査は行わない。

### 2. 対象の偏りと保存負担を改善する

英語編集部あらすじ中心の少数標本を世界の小説の代表にしない。現在の言語・年代・ジャンルの不足から次の対象層を固定する。新しい根拠を得られる未調査経路だけを最大2経路・45分まで確認し、終了済み経路と保留入力を再送しない。

現行形式は、実行ごとに固定資料や公開画面・DB・証拠の複製を保持するため保存量が大きい。まず固定負担と作品ごとの増分を分け、必要な場合だけ既存の検証・取消可能性を保った共有化を行う。索引・埋め込み・ベクトルDB・クラウドは実測上の必要が出てから追加する。

### 3. 新しい対象だけで段階測定を続ける

対象を最大20件で取得前に固定し、書誌と内容根拠を区別して6用途を検査する。成立0件ならモデル0回。最初は最大10作品、最大5作品/call・2並列、分類と別審査の合計4呼出・モデル工程20分・観測token50万を上限とする。時間・利用量を固定し、無料残枠を無制限と仮定しない。

採用率70%以上・出力検証保留5%以下、用途・証跡・資源条件を満たす場合だけ次段階へ進む。DB保存件数を採用件数にせず、全採用・ラベル単位採用・保留を分け、実際の表示を確認してから判定する。採用済み・不確実なnative結果やconfidenceは変更しない。

追加分の既読除外、出典、撤回・復旧、変更外候補の不変を確認する。関連度や分類軸の不足はunknownのまま保持する。既存の8作品・2作品の測定は新しい比較理由なしに繰り返さない。

### 4. 拡張の条件を満たしてから増やす

1万件の同形式処理は概算で全工程約81〜226時間、分類・審査約124〜521百万token、証拠・複製保存約28〜162GB＋固定資料という広いシナリオ範囲。小標本の固定負担を含み、取得可用数・品質・納期や無料運用の保証ではない。実装改善や対象層の変更後は成立分だけ見積もりを更新する。

| 段階 | 進める条件と届けるもの |
|---|---|
| 1,000〜3,000作品の限定PoC | 作品・翻訳・版の台帳、検索、既知の既読除外、理由と出典。収録数・特徴数・得点可能数・用途・同定の未評価範囲を分ける |
| 100作品以下の代表性補完 | 追加対象の層と資源条件を固定。取得・審査・推薦・差分・復旧を実測し、既存の少数英語標本の偏りを補完する |
| 1万作品 | 用途確認済みの無料書誌で不足層を補う。大量AI分類は独立品質・代表的処理量・無料残枠が成立してから |
| 3万作品 | 1万段階の実測で差分処理を拡張。履歴接続・評価入力が成立した範囲だけ推薦比較と漏洩検査を行う |
| 10万作品以上 | 異なる小説・LNの台帳、検索・推薦、新規/変更/撤回のみの更新、バックアップ・復旧を実証する |
| ToC提供候補 | 詳細、理由、既読管理、訂正・削除、用途別帰属、個人履歴の保管・削除、無料で維持できる条件を整える |

主要ラベルprecision 0.85・recall 0.65、高信頼採用precision 0.95、自動名寄せprecision 0.99の[品質目標](quality-evaluation-protocol-v1.md)を維持する。現在は未評価であり、内部審査・採用率を独立正解へ置き換えない。未記載タグも負例へ置き換えない。

## 作業・報告の条件

- 購入・外注・有料API・本人への追加入力・試読・採点依頼は行わず、有料化へ自動移行しない。
- 履歴接続は原連載・対象版・内容根拠が新しく成立した場合だけ追加し、入力が増えた場合だけ既存比較を一度行う。
- 原DB・raw・分類版・実行証拠を保持し、新規・変更・撤回だけを処理する。個人履歴・引用本文・DBはGitへ含めない。
- 成果のまとまりごとにコミット・pushし、必要な試験とCIを確認して許可済みの範囲でマージする。Markdownのみの変更でモデル・DB生成・全件試験を再実行しない。
- 進捗は増分、測れた品質・性能、残る不足、次の固定対象で報告する。版数・呼出回数を成果数の代わりにしない。
- 全体納期は対象層・処理量・無料残枠の実測で更新する。10万作品の完了日は確約しない。

現在、ユーザーの回答が必要な事項はない。今回の1〜5は上記の限定範囲で実施済みであり、将来段階の大量処理を許可済み・達成済みと扱わない。
