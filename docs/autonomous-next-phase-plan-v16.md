## 次に進める4項目

### 1. 作品単位の書誌・版対応の不足を補う

保存済みのメタデータ一覧と保留理由を再利用し、原作品・表現・刊行版・シリーズの区別、原題・訳題・著者ID・原言語・初出年・国地域の不足から、修正可能な差分を選ぶ。最初の確認対象は最大20関係に固定する。国地域を著者国籍で代用せず、タイトルやISBNだけで統合しない。

成果物は対象別の根拠・修正・保留と、取消可能なID対応。診断済みの重複2組・複数外部ID1作品は、新しい根拠なしに再診断しない。同じ全件集計・大きな旧DBのコピーや全量hashも繰り返さない。

### 2. 新しい分類入力が成立する対象を確保する

書誌の補完と紹介文・内容根拠の補完を分ける。保存資料を優先し、具体的な未調査の公式経路がある場合だけ、1回の資料探索を最大2経路・45分に区切る。取得対象・リクエスト数の上限を先に固定し、終了済みの経路は再探索しない。新規取得時にはその時点の公式条件を確認する。

作品・版の厳密対応と、取得・保存・外部AI入力・表示・再配布・商用の用途検査を満たした入力だけを次の最大20作品として固定する。成立0件なら分類0回で終了する。入力・根拠が変わらない保留を、追加LLM呼出で埋めない。

### 3. 成立分だけ分類し、限定PoCへ反映する

次バッチはまず最大10作品を処理する。Codex Sol CLIは最大5作品/call・2並列を基本とし、分類と別呼出の審査を行う。最大10作品の1段階は分類・審査合計4呼出、モデル工程20分を上限とする。採用率70%以上・出力検証保留5%以下、用途・実行証跡・資源上限を満たした場合だけ、同じ上限の次段階で残りの対象へ進む。これは運用目標であり、独立した分類精度ではない。

採用分だけDB・検索・推薦理由・出典へ反映し、既知の既読除外、撤回・復元、変更外の候補の不変を確認する。根拠、対象表現、6軸の分類、関連度、未校正confidence、処理版を保存し、資料不足の軸はunknownにする。失敗した同じ入力の自動再送は行わない。各実行の時間・利用量上限を固定し、無料残枠を無制限と仮定しない。

### 4. 限定PoCをまとめ、100作品以下で全工程を測る

1,000〜3,000の異なる小説・LNという対象条件を確認し、収録数・特徴数・得点可能数・用途別可否・未確定な同定を別々に報告する。全件得点や独立品質目標が未達なら、未評価範囲を明示した限定PoCとして届ける。書誌上の1,440保存IDだけで原作品の件数目標を達成済みにしない。

20作品段階の入力成立率・採用・資源が成立した後に、新しい対象を100作品以下で固定し、取得から審査・推薦・差分更新・中断再開までの全工程を測る。ここで初めて1万作品の時間・token・容量を範囲で見積もる。前回のモデル約55秒を大量処理へ単純外挿しない。

## 履歴接続と独立評価の再開条件

- 履歴は原連載IDと対象版・内容根拠が成立した場合だけ接続する。接続数か評価入力が増えた場合だけ、既存の固定仕様で推薦比較を一度行う。本人の追加入力・試読・採点は依頼しない。
- 独立評価は分類定義・作品同定・明示的な正負注釈・利用条件が合う新資料が得られた範囲だけ再開する。未記載タグを負例にせず、Codex審査を独立正解へ変更しない。
- 新しい根拠がなければ保留・未評価を維持する。独立正解不足だけで通常の書誌補完や限定修正を止めず、同じ探索を無期限に続けない。

## 最終ゴールまでの順序

| 段階 | 届けるもの・進める条件 |
|---|---|
| 1,000〜3,000作品の限定PoC | 作品・翻訳・版を区別するDB、検索、既知の既読除外、推薦理由と出典。対象件数・用途・coverage・未評価範囲を確認 |
| 100作品以下の全工程実測 | 入力成立、審査、採用、更新・復旧の実測。調査・開発・CI待ちとモデル工程を分け、次段階の資源上限を決定 |
| 1万作品 | 用途確認済みの無料書誌で言語・国地域・年代・ジャンルの不足を補完。書誌収録数と分類・推薦可能数を分ける。大量AI分類は品質・対象構成・代表的処理量・無料枠が成立してから |
| 3万作品 | 1万段階の実測から差分処理を拡張。履歴接続が成立した範囲だけ既存比較方式と推薦を比較し、漏洩を点検 |
| 10万作品以上 | 異なる小説・LNの台帳、検索・推薦・新規/変更/撤回だけの更新、バックアップと復旧を実証。全世界・全ジャンルの品質保証とは分ける |
| ToC提供候補 | 作品詳細、理由、既読管理、訂正・削除、商用利用できる項目と帰属、個人履歴の保管・削除、無料で維持できる運用条件を整える |

ToCの準備は既存データで並行できる。索引・埋め込み・ベクトルDB・クラウド基盤は実測や公開範囲から必要になった部分だけ追加する。新たな本番公開の影響がある判断は、具体的な成果物とともに報告する。

主要ラベルprecision 0.85・recall 0.65、高信頼採用precision 0.95、自動名寄せprecision 0.99の[品質目標](quality-evaluation-protocol-v1.md)を維持する。独立正解、対象構成、代表的な全工程処理量、無料残枠は未確定のため、現在は1万→3万→10万作品の大量処理を開始しない。

## 作業と報告のルール

- 購入・外注・有料API・本人への追加評価依頼は行わない。有料化へ自動移行しない。
- 原DB・raw・台帳・分類版・実行証拠を保持し、新規・変更・撤回だけを処理する。個別履歴・評点・引用・DBはGitへ含めない。
- 成果のまとまりごとにブランチ・PRでコミット・pushする。コード変更には必要な試験・最終版CIを行い、許可済みの範囲でマージする。文書だけの変更でモデル・DB生成・全件試験を再実行しない。
- 進捗は増えた作品・特徴・履歴接続、測れた品質・性能、残る不足、次の固定対象で報告する。計画書の版数や呼出回数を成果数の代わりにしない。
- 全体納期は100作品以下の実測後、1万・3万の実績で更新する。現時点で10万作品の完了日を確約しない。

現在、ユーザーの回答が必要な事項はない。この文書更新は実データの新規処理や規模拡張の実行を含まない。
