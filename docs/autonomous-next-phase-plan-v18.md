# 次の計画：3万作品への拡張と内容特徴の充実

更新: 2026-10-20。[v17](autonomous-next-phase-plan-v17.md)の1〜4は完了した。開始時の実績は検索可能11,383作品、資料ジャンル特徴11,382作品、新規Sol分類1,000作品、そのうち表示できる詳細特徴888作品。[実施結果](scale-catalogue-v1.md)を基準に、3万作品への拡張を実行中である。

## 現在地と直近の順序

書誌拡張は目標に到達した。現在は保存32,130作品、検索可能32,126作品、資料に基づく推薦対象24,741作品。目標到達後、書誌の追加取得は停止した。[現在の結果](scale-catalogue-v2.md)を参照。これらは資料が小説と記す作品IDの件数であり、原作品を独立に検証した件数ではない。

内容資料を使う最初の100作品は分類が正常終了した。失敗0件だが、別審査・公開条件の検証前なので、分類済み・表示採用の累計にはまだ加えない。全件審査の入力がCLIの文字数上限を超えたため、分類結果を保持して審査だけを50作品ずつに分割した。既存1,000作品を保持し、追加4,000作品で累計5,000作品にする。

直近は次の順序で進める。書誌3万件の提供は内容分類の完了を待たず、現在の台帳で利用できる。

1. 修正・回帰試験を通した内容収集で、未試行作品だけを継続取得する。保留作品の再選択を防ぎ、取得の自動再試行を止め、取得制限・キャッシュを共用する。既存資料もユニークな作品IDで数え、用途判定を通った件数とは区別する。
2. 実行中の最初の100作品を終え、全件を別審査する。採用した内容根拠だけに出典・版・寄稿者履歴・利用条件を結び付け、生成した分類・引用レコードの公開条件を別工程で検証してから画面へ反映する。
3. 最初の100作品が下記の継続条件を満たしたら、同じ仕組みで未処理作品の資料補完・分類を継続する。並列数の追加は実際の速度・失敗・利用枠を確認してから行い、入力や実行環境の作り直しは繰り返さない。
4. 検索3万作品・分類累計5,000作品・6軸別の採用と不明を実データで確認する。検索・詳細・推薦・出典表示を確認し、READMEと結果報告を更新して、適切な区切りでコミット・push・CI・マージする。

本人の追加採点・確認待ちは設けない。件数、原出力、審査後の採用、画面で使える特徴を分けて報告する。

## 次の到達目標

**検索・類似推薦に使える小説台帳3万作品と、ジャンル以外の内容特徴を増やす継続処理を提供する。** 書誌拡張は詳細分類・本人評価・個人推薦の完成を待たずに進める。詳細分類の次の規模目標は新台帳で累計5,000作品とするが、根拠の乏しい同一入力の再分類で件数を稼がない。

追加費用0、外注なし、追加本人作業0を維持する。既存Codex CLIのSolと無料で条件の合う資料を使う。通常の取得・実装・試験・コミット・push・許可済み範囲のマージはCodexが判断する。

## 実行する順序

| 順序 | 作業 | 到達点・継続条件 |
|---|---|---|
| 1 | 既存の分割取得を継続し、11,383→30,000作品へ増やす | 対象小説の異なる作品ID3万件を検索へ反映。版・短編・シリーズ全体を水増しせず、同じIDの重複0。資料ジャンル等の根拠がある推薦候補2万件を目標とし、不足は別集計する |
| 2 | 1と並行して内容資料を補う | あらすじ・解説・利用可能な本文について、作品同定と用途条件が成立する資料を追加。最初の200作品で増分処理を確認後、成立した経路の未処理分を継続し、再計画・再承認は挟まない |
| 3 | 内容資料のある作品を優先してSol分類を増やす | 新台帳で累計5,000作品を次の目標とし、6軸ごとの採用・保留・不明を表示。ジャンル以外の採用が増えない入力経路は資料補完へ戻す。書誌の3万件提供は止めない |
| 4 | 好みを指定して候補を探せる推薦を強化する | 好きな作品・ジャンル・年代・言語・避けたい特徴から候補を選べ、理由・既読除外・根拠不足を表示する。新しい採点や試読は依頼しない。履歴接続が不十分な場合も類似推薦を提供する |
| 5 | 3万件の実データで確認し、10万作品へ継続する | 差分更新・検索・詳細・推薦・保留反映が動くことを確認。実測された遅い箇所だけ改善し、未確認の精度を保証せずに書誌と内容特徴を増やす |

1は直ちに着手できる主経路であり、2・3の資料探索や精度検証の完了を前提にしない。4の好み指定は利用機能であり、ユーザーが入力しないと開発を進められない条件にはしない。

## 取得と内容資料の扱い

書誌は既存Wikidata経路のチェックポイント・raw・キャッシュ・用途判定を再利用し、1,000件単位で保存する。言語・年代別の不足も集計し、日本語・非英語・現代作品を対象に含める。抽出できた範囲の偏りは明記する。原作品の独立検証済み件数と、資料が小説と記す作品ID件数は区別する。

内容資料は保存済みの利用可能な資料を先に確認する。新しい補完経路の初期調査は最大2経路・各1回とし、用途条件と実際に得られる内容を確認して成立する方を使う。Open Library・NDL等は条件と取得方法が確認できた不足補完だけに使い、申請待ちや権利不明の経路を全体の前提にしない。同じ不成立経路を新しい根拠なく調べ直さない。

作品・翻訳・版の対応は、明示的な作品関係・著者・識別子・資料を保存して扱う。題名が似ているだけでは統合しない。内容資料の使用許可はAI入力・表示・再配布・商用利用で分ける。AI入力だけ成立する資料はそのまま画面へ転載せず、表示できる特徴・根拠の範囲を別に判定する。リンク先本文へ書誌のCC0を引き継がない。

## Codexと検証の使い方

取得、内容資料の準備、分類、画面改善は依存しない範囲で並行する。Sol CLIは既存の最大4並列・最大5作品/呼出から継続する。token量を過度に節約して必要な分類を止めない一方、モデル混雑・利用枠通知・実際の処理速度を確認せず並列数だけを増やさない。

新しい入力経路では最初の100作品を全件別審査し、スキーマ・根拠・用途の失敗5%以下、実際の表示特徴採用70%以上、モデル工程1時間・観測200万token以内、利用枠制限通知なしを継続条件にする。既に成立した経路の前処理・初回検証を毎回作り直さない。審査頻度は実際の不一致に基づいて決め、根拠・用途・出力と作品の結び付きは毎回維持する。

採用率は正解率ではない。LLM同士の一致、人手正解による精度、既存履歴での推薦評価は別に報告する。内容資料を追加したときだけ、その新しい入力に対して不足軸の分類を行う。同じ作品の更新でユニーク分類作品数を増やさず、既存結果と入力版を保持する。根拠が足りない項目は不明のまま残す。

エラー時は原出力とチェックポイントを保存し、影響した入力・経路を保留する。同じ失敗入力の自動再送、モデル枠を探る定期probe、有料APIへの切替は行わない。利用枠通知があればモデル処理を止め、成立する書誌・画面作業を続ける。

## 性能・履歴と品質

拡張開始前のAPI中央値は一覧2.63秒、詳細1.33秒、類似候補3.49秒、統計6.13秒だった。資料情報だけを返す一覧・類似推薦で不要な分類証跡の照合を省き、11,383作品時点のバックエンド各2回の測定では一覧中央値151ms、類似推薦183ms、分類特徴を返す詳細1,402msとなった。HTTP・負荷試験とは区別し、3万作品と分類追加後に必要な確認を行う。詳細・統計での分類証跡の照合は維持する。分類を増やす際は検証・SQL・表示のどこが増えるかを計測し、照合の重複や索引など実測箇所だけを改善する。日時だけで証跡照合を省略する変更はしない。変更・撤回・破損時の反映も確認する。性能改善は書誌収集と並行し、試作全体の作り直しを先に置かない。

335評価の全件照合は再実行せず、新しく得た書誌関係・内容資料で対応が変わる対象だけ更新する。確実な接続、曖昧な接続、内容根拠の接続を分ける。評価可能な接続が増えた範囲で履歴を分割し、ジャンルのみと内容特徴ありの推薦を比較する。同一作品の別版や同一シリーズによる評価漏洩を点検し、母数・不足を明記する。人手正解や本人の追加採点は完了条件にしない。

現在はテーマ・構造・雰囲気の採用が少なく、主人公・文体は1,000作品すべて不明である。この不足はtoken量だけでは解消しない。次の分類では内容資料によって実際に増えた軸別の特徴を成果として報告する。

## 3万作品の後

3万件で差分取得・対象種別・検索・推薦・保留反映を確認したら、同じ仕組みで10万作品へ進む。全作品の6軸分類や独立精度評価の完了は書誌拡張の前提にしない。分類は資料がある未処理作品から別の進捗として増やす。

ToC候補は、公開するデータの表示・商用利用条件、個人履歴の保管・削除、追加費用なしの運用が成立する範囲で用意する。一般公開・運用条件が成立するまではローカルで利用できる成果を維持する。10万作品が揃うまで利用機能を届けない計画にはしない。

## 無駄を増やさない運用

進捗は検索対象数、推薦特徴あり、ユニーク分類済み、軸別の採用・不明、確実な履歴接続、実時間と利用量で報告する。件数ごとの再承認や計画書更新は挟まない。環境・DBの全コピー、変更していない入力の再分類、関連のない全テスト・CIの重複実行を避ける。変更に必要な試験だけを行い、実装の区切りでコミット・pushする。

書誌3万件の反映は完了した。次は最初の100作品の別審査・公開反映と、重複を除いた内容資料200作品の実測から、詳細分類の残りの処理速度を更新する。内容資料の充足率と審査の採用率が未確定なため、未測定の全工程の納期は断定しない。

本計画はv17の完了後の実行順を更新する。v17の固定条件・過去の実績・原出力は変更しない。
