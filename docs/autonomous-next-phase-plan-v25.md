# 日本のライトノベルを必須対象にする収録・統合計画

更新: 2026-10-25 06:12 JST。[v24](autonomous-next-phase-plan-v24.md)を更新する。無料資料と既存Codexだけを使い、購入・外注・本人による追加入力や評価は求めない。通常の判断、実装、確認、commit・pushはこちらで行う。変動する件数と検証結果は[進捗](light-novels-progress-v1.md)に集約する。

## 目標と現在地

日本のライトノベルを、世界小説の推薦システムの必須対象として扱う。現行の主要レーベルだけでなく、旧作・廃刊レーベル、女性向け、Web小説の書籍化、電子限定作品を対象にする。「魔法科高校の劣等生」は検索・詳細・好み指定・推薦まで確認済みだが、日本のライトノベルをほぼ網羅した段階ではない。

シリーズの登録・版確認・出版社書誌対応・内容分類は、それぞれ別の進捗として管理する。現在の件数は[進捗の「現在使える範囲」](light-novels-progress-v1.md#現在使える範囲)を参照する。候補書誌や取得した商品一覧を、そのまま推薦可能な作品数へ換算しない。

## ここからの実施順序

| 順序 | 作業 | 次へ進む条件 |
|---|---|---|
| 1. 取得済み資料を検索できる書誌へ接続 | 既存の出版社との接続済み根拠を保持し、オーバーラップ、集英社DX、双葉社Ｍノベルス系の差分を接続する。新経路は少数の実例で検証してから対象の差分へ広げる | 確認済み・未対応・保留を分け、新たに検索可能になった書誌を実際に確認する。旧版確認・分類・履歴を保持する |
| 2. 不足する取得枠を埋める | 取得中のKADOKAWA追加5レーベルを終端まで進め、完了した枠を照合する。続いて講談社・双葉社等の未取得系統、旧作・廃刊、女性向け、電子限定を取得台帳の不足順に補完する | 各枠の総数・最終ページ・重複・取得失敗を記録する。GC系のHTTP 500や講談社のメンテナンス転送は保留を残し、新しい根拠なく同じ失敗や回避経路を繰り返さない |
| 3. シリーズ・各巻・版を整理し、推薦へ接続 | シリーズ名・各巻の固有題・別題・著者で検索できるようにする。公式の明示関係とNDL主書誌を照合し、既存504シリーズの内容特徴を利用する | シリーズ自身や同一作品の版が推薦を占めず、既読除外と推薦理由が働く。未分類の書誌も検索でき、特徴不明を推測で埋めない |
| 4. 品質・範囲を確認して反映 | 誤結合、巻違い、重複、出典、取得・AI入力・表示・再配布・商用利用の条件を確認する。変更した経路の実HTTP・画面確認と確定実装のUbuntu／Windows Python 3.14 CIを行う | 結果と残作業を文書へ反映し、commit・push・PRにまとめる。主要な取得枠・大量未対応が残る間は「ほぼ網羅」や完成としない |

取得と接続を大きな二工程に分離せず、出版社ごとに取得→照合→検索確認まで進める。取得だけ済んだ一覧を増やし続けない。並列化は独立する提供元・実装・レビューに用い、同じ提供元へのアクセスとDB書込みはそれぞれ一系統にする。

## 次の実行単位

1. オーバーラップは追加NDL候補の取込みと最初の実対応を確認した。取得済み3ブランド639参照のうち個別詳細未取得635件を有限取得し、終端後に正式検証・保存NDL書誌との照合へ進める。既取得4詳細は再取得せず、無標記の人名も著者と推定しない。
2. 双葉社Ｍノベルス／Ｍノベルスｆは616参照の正式検証と151件の書誌対応を終えた。次は公式の作品グループを根拠に、作品名から各巻をたどる接続を追加する。1群21参照は公式の「既刊」と一覧終端を確認済みで、保存616参照中の他のグループにも利用できる根拠を確認する。作品グループと物語シリーズを区別し、ISBN不明100参照も残す。
3. KADOKAWAのMFブックス、カドカワBOOKS、ファミ通文庫、角川ビーンズ文庫、ビーズログ文庫は収集中の結果を利用する。取得終端を確認後、未照合の差分だけを既存経路へ接続する。旧4レーベルは再取得しない。
4. 集英社DXの追加383版の確認と既存シリーズへの29版の接続を終えた。残る対応は新しい公式関係・巻表示・著者典拠がそろった差分に限定する。女性向け・旧作・電子専売の未取得と未対応を台帳に残し、不足の大きい取得枠を次に進める。電子版と紙版、合本と単巻を根拠なく統合しない。

これらをまとめた実装の区切りで関連試験、変更経路の実HTTP・画面、両OS CI、文書、commit・pushを行う。取得待ちの間に既存の成功済み処理を繰り返さない。

## 照合と分類の基準

ISBN・完全な書名・巻次・著者役割・出版社・レーベルなどの複合根拠で対応を確認する。出版社サイトの現在の運営元と、各書誌に記録された出版者を分け、旧出版社名を現在名へ一括変換しない。版限定の表記対応を全作品の別名規則へ広げない。漫画化、アニメ化、合本、特典付き商品を原作シリーズへ一括統合しない。

分類はジャンル、テーマ、物語構造、主人公属性、文体、雰囲気を多ラベルで扱い、関連度・未校正の信頼度・根拠・分類版を保存する。本文根拠のない文体は不明のままにする。既存504シリーズの内容特徴を利用し、既存分類の再実行や全件分類を収録拡張の前提にしない。新規分類を再開する場合は、用途条件が確認できる新しい内容資料のある差分だけに限定し、既存Sol CLIの分類と別呼出しの審査を独立した入力単位で並列化する。

独立した正解集合のない分類精度、信頼度の校正、本人向け推薦改善は未評価として報告する。本人の採点や外部評価の購入は要求しない。

## 無駄を増やさない運用と完了判定

保存済み原資料と既存の検証結果を再利用し、新しい根拠・変更のある候補だけを再処理する。全件再取得、同じ入力の再分類、固定20シリーズの再確認、世界小説2万分類の全件再監査は繰り返さない。関連試験は変更時に実行し、全体CIはまとまった実装の区切りに一度行う。経過時間や残量は実測から更新し、根拠のない完了予定を出さない。

全国の全刊行物という確定分母はないため、網羅率の数字を作らない。出版社・レーベル・年代・形式ごとに、一覧総数、取得済み、版確認済み、シリーズ対応済み、未対応、保留、対象外を示す。主要な既知の不足を解消し、残る取得不能・権利不明・電子限定等を説明できた時点で収録範囲を評価する。1,000シリーズ・500内容分類は通過点である。

ライトノベルの収録と利用が安定した後、差分更新へ移し、世界小説の内容分類を3万・5万・10万作品以上へ広げる。ToC化は用途条件、履歴管理、応答時間、公開構成を確認して判断する。
