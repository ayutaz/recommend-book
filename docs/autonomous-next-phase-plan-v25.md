# 日本のライトノベルを必須対象にする収録・統合計画

更新: 2026-10-25。[v24](autonomous-next-phase-plan-v24.md)の後続計画。日本のライトノベルの収録不足を、世界小説の分類数拡大より優先する。無料資料と既存Codexだけを使い、購入・外注・本人による追加入力や評価は求めない。通常の判断、実装、確認、commit・pushはこちらで行う。

## 目標と現在地

現行・旧作・廃刊レーベル、男性向け・女性向け、Web小説の書籍化、電子限定作品まで対象にする。一般小説との境界や翻訳作品は出典に従って区別し、日本語の書誌を日本語原著と決めつけない。シリーズ名・各巻名・別題・著者で検索し、好きな作品や読書状態から別作品を推薦できることを目指す。

現在は2,197物語シリーズ、内容特徴572シリーズを登録済み。「魔法科高校の劣等生」は検索・詳細・好み指定・推薦を確認済み。版候補86,446件にはラノベ未確定の書誌も含むため、推薦可能な作品数へ換算しない。確認値と過去の作業記録は[進捗](light-novels-progress-v1.md)に集約する。日本のライトノベルをほぼ網羅した段階ではない。

## 実施順序

| 段階 | 実施内容 | 完了を判断する条件 |
|---|---|---|
| 1. 未接続の書誌を追加 | 取得済み資料とDBのID差分だけを採用する。富士見L、講談社BOX／タイガ、星海社FICTIONS／文庫、キャラの6枠とシフォンの差分採用は終了した。次の未取得枠も有限な範囲で接続する。出典・実叢書欄・言語・出版者・分類記号を保持し、未同定でも候補として検索可能にする | 新規IDの採用結果と旧IDの保持を確認。名称検索のヒットと実際のレーベル所属を区別し、候補・不明の表示が働く |
| 2. 作品・シリーズ・版を対応付ける | 公式一覧とNDL主書誌の複合根拠で、シリーズ、各巻の作品、紙・電子・文庫版を分けて接続する。完全題・巻次・著者役割・ISBN・出版情報を確認し、同名作品、短編集、翻訳、漫画化を区別する | 根拠のある関係だけを保存。正式名・各巻名・別題で検索でき、巻違い・誤結合を検査できる。未証明は独立した書誌として残す |
| 3. 内容分類と推薦へ接続 | 用途条件と内容根拠のある未試行差分だけをSol CLIで分類し、別呼出しで審査する。ジャンル、テーマ、構造、主人公属性、文体、雰囲気に関連度・未校正の信頼度・根拠を付ける | 書誌ジャンルと内容特徴を区別して推薦理由を表示。同一シリーズ・同一作品の別版の重複を抑え、既読除外と状態不明の扱いを確認。根拠のない軸はunknownのまま |
| 4. 不足と利用品質を確認して反映 | レーベル・年代・形式別に取得済み、対応済み、保留、未取得、対象外を整理する。変更箇所の試験・実HTTP・必要な画面確認・実装更新時の両OS CIを行い、文書・commit・push・PRへ反映する | 既知の大量未対応を解消し、残る取得不能・電子限定・権利不明を説明できる。分類数や検索件数だけで「ほぼ網羅」と判定しない |

各提供元で取得→差分採用→名寄せ→検索確認を一区切りにする。取得だけの一覧を増やし続けず、内容未分類でも検索に使える状態を先に作る。第4段階の不足を次の取得枠へ戻し、対象範囲を広げる。

## 利用条件・分類品質

取得、AI入力、表示、再配布、商用利用の条件は用途別に記録する。書誌の利用許可を紹介文・本文・表紙画像へ広げない。用途不明の文章をLLMへ渡さず、書誌や出典リンクだけを扱える範囲と分ける。将来のToC提供は公開対象と用途条件が成立した段階で判断する。

分類は根拠区間、モデル・分類体系・入力の版、関連度、信頼度を保存する。本文根拠のない文体は不明のままにする。LLMの別審査は品質検査であり、独立した正解集合ではない。独立精度・信頼度校正・本人向け推薦改善は、証拠が得られるまで未評価と報告し、本人の採点を完成条件にしない。

## 時間と処理量を抑える運用

- 保存資料と既存の成功証跡を再利用し、新しい根拠・変更・未登録IDのある差分だけを処理する。全件再取得・原資料の再監査・同じ入力の再分類を繰り返さない。
- 独立する取得元、名寄せ、実装、レビューを並列化する。同一提供元へのアクセスとDB書込みは各一系統とし、失敗時の無制限な自動再試行をしない。
- Sol CLIは独立した未試行入力を並列実行する。既存の検証済み契約を使い、上限8ワーカー以内で失敗率と実測時間を見て調整する。
- 試験は変更箇所に合わせる。ce76104のWindows打切りは既存fixture群の累積時間によるもので、新66試験の所要時間だけが原因ではなかった。実装08d9530では試験を省かずWindowsのみ上限25分へ調整し、両OSのCIを1本だけ実行中。データ・計画だけの更新で再起動しない。
- 世界小説の既存2万分類と読書状態を保持する。原資料・DB・読書履歴はGitへ含めない。

固定件数への到達は通過点とする。既知の取得枠の不足と対応保留を解消し、残る空白を説明できるようになってから収録範囲を評価する。所要時間は次の実行単位の実測から更新し、全国網羅の完了日時は現時点で断定しない。ライトノベルの収録・利用が安定した後、差分更新へ移して世界小説の3万・5万・10万作品以上へ拡張する。
