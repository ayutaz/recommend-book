## 1. 不足と利用可能な資料を一度整理する

現在の台帳、保存済み資料、過去の予約・失敗・保留を再利用し、未処理で用途条件と作品対応が成立する資料を抽出する。日本語、ミステリー・ファンタジー・ライトノベル、年代別に、検索可能数・分類済み数・表示特徴数・資料の不足を分ける。国・地域は保存済みの根拠がある範囲だけ集計し、不明は不明として残す。

この集計で優先対象と投入可能件数を決め、すでに処理した作品を除いた次段階のID・入力・条件・既存1万分類の比較用記録を別の出力先へ固定する。ジャンルが分からない作品を分類済みジャンルの分布へ混ぜない。世界全体の代表標本や日本語作品数の増加を、資料の在庫確認前に保証しない。

**移行条件:** 優先順位、実際に投入できる新規資料数、資料不足の区分、差分反映先が確定していること。全区分の資料が揃うまで、成立済み区分の処理を待たせない。

## 2. 新規の詳細分類を累計2万作品へ差分追加する

成立した資料から処理し、使える区間ごとに検索・推薦へ反映する。既存1万作品の一括再分類、全10万作品の一括分類、書誌20万件への拡張を必須工程にしない。資料不足の対象だけ無料の補完経路へ戻し、新しい根拠がない同じ経路の調査は繰り返さない。追加経路の適合性調査は最大2経路・各1回とし、利用拒否や保留を回避する取得は行わない。

既存の分類・別審査・用途確認・台帳採用の工程を再利用する。Sol CLIは最大8並列、1呼出し最大5作品を維持し、成立済みの1作品/分類呼出しと既存の4/8並列制御を使う。書誌・資料準備と分類は独立する範囲で並行し、DBへの書込みは一つの担当にする。残数未満の入力が必要な場合は必要分だけ別途固定し、元のmapや入力を書き換えない。

失敗率5%以下・実際の表示特徴採用70%以上の既存条件を維持する。失敗した同じ入力を自動再送せず、引用・作品ID・入力hash・用途・採用ラベルの対応を保持する。本文根拠のない文体は不明とする。

**完了条件:** 既存10,000分類を保持し、新規採用10,000作品を追加して累計20,000となること。表示特徴あり、内容根拠付き非ジャンル特徴、6軸の採用・保留・不明、言語・年代別の実数、実時間とCLI報告の利用量を報告する。資料不足で届かなければ、到達数と不足をそのまま記録し、目標達成とはしない。途中の成果も順次提供する。

## 3. 待ち時間とローカル利用を並行して整える

分類拡張と別系統で、既存profileが示した証跡確認などの律速箇所を調べる。まず小さく検証できる改修を1区切り行い、同じ条件の実HTTPを各1回測定する。証跡の破損・変更・撤回・用途保留の検出、推薦順位・理由・除外を維持する。日時だけで認証を省略せず、閲覧時にLLMを呼ばない。

追加改修は残る律速や回帰の新しい証拠に基づいて決める。性能の再調査を理由に差分分類・途中反映を止めない。応答時間は測定条件と回数を添え、負荷試験や性能保証と区別する。

既存の読書状態保存と再起動後の保持を確認し、履歴の削除・持ち出しを必要な範囲で実装・検証する。fixtureによる削除確認は実際の本人履歴へ適用しない。READMEの起動手順と、Git対象外データが必要なことを利用者に分かる形で保つ。

**完了条件:** 変更した経路の関連試験と実HTTP・必要な画面操作が通過し、待ち時間と残る制約を記録すること。保存・削除・持ち出し・再起動の挙動を、個人データを公開せず確認できること。

## 4. 成立する範囲で評価し、ToC候補へ進む

既存335評価は、新しい作品関係や資料で対応が変わった対象だけ照合する。評価可能な母数が成立した場合に、資料ジャンルのみと内容特徴を使う推薦を同じ対象で比較する。作品・翻訳・著者・シリーズによる評価漏洩と、使えなかった評価の件数を報告する。対応が足りなければ評価不能とし、本人向け改善を宣言しない。

独立した分類精度・確信度の校正・名寄せ精度は、[品質評価仕様](quality-evaluation-protocol-v1.md)に沿う。新たな無料の適合資料が得られた範囲だけ評価し、同じ注釈の探索や全件審査を反復しない。LLM同士の一致を独立正解とせず、本人への追加採点や有料データ・有料APIへ切り替えない。独立評価が成立しなくても、機能提供と差分拡張は続けられる。

ToC候補では、表示・再配布・AI入力・商用利用を用途別に確認し、履歴の保存先・削除方法・持ち出しと無料運用範囲をまとめる。無料資料だけで一般公開・商用利用まで許可されるとはみなさない。一般公開は、必要な機能・権利条件・データの扱い・実際の公開構成が成立した段階の別作業とし、ローカル利用と区別する。
