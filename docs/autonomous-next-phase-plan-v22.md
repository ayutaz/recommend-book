# 次の計画：日本のライトノベルを検索・推薦の必須対象にする

## 解消する問題と完了条件

現行のローカル台帳で「魔法科高校の劣等生」は日本語名・英語名とも未収録だった。現在の取込みは個別小説を対象にシリーズを除外するため、[Wikidataでライトノベルシリーズとして登録される項目](https://www.wikidata.org/wiki/Q5357270)を検索・推薦に利用できない。日本語作品を優先するだけでは、この構造的な漏れは直らない。

最初の完了条件は、**「魔法科高校の劣等生」で検索し、小説シリーズとして詳細を開き、好きな作品に追加して、別作品の推薦を理由・出典付きで受け取れること**。書名だけを追加して完了とはしない。その後、日本のライトノベルを100、1,000シリーズへ広げる。シリーズ数・各巻の作品数・版数・内容分類数は別々に報告する。

日本語で執筆されたライトノベルを中心に扱い、他言語訳も同じ原作品への関係として管理する。Web版・書籍版・続編・外伝・漫画・アニメは区別する。日本語のタイトルがあることだけで、日本のライトノベルと判定しない。レーベル名やNDCだけでも確定せず、資料にある種別・出版情報などの根拠を保存する。

既存の検索可能100,370作品・詳細分類20,000作品と最終監査は[到達済みの結果](scale-catalogue-v4.md)として保持する。今回のシリーズ追加を、従来の詳細分類件数へ加算しない。独立精度・確信度の校正・本人向け改善は引き続き未評価である。

## 1. 既存資料を棚卸しし、収集経路を二つに絞る

保存済みWikidata・NDL・従来PoCの資料を一度確認し、取得済みデータを再利用する。過去の保留は理由と入力hashを保持し、新しい取込み契約に適合する根拠がある対象だけ別バージョンで審査する。同じ失敗入力の再送や、既存分類のやり直しは行わない。

| 経路 | 主な用途 | 取込みの条件 |
|---|---|---|
| Wikidata | 小説シリーズの識別子、日本語名・別題、著者、原言語、ジャンル、明示された巻との関係 | シリーズを独立種別で取得する。アニメ・漫画の同名項目を除き、関連本文や画像へメタデータの条件を広げない |
| NDL作成の書誌・典拠データ | 各巻の題名・巻表示、著者、出版社、刊行年、ISBN、版の対応 | 提供機関・レコードIDと出典を保持する。NDLサーチ経由の他機関データを同じ条件で一括採用しない |

NDL自身が作成した書誌等は、営利・非営利を問わず無償利用できるが、本文は含まず、第三者作成データは別条件である。[NDL公式の案内](https://www.ndl.go.jp/data/data_service/quickguide)に従って対象を選ぶ。APIの手続き・クレジット・アクセス制限は[公式API利用案内](https://ndlsearch.ndl.go.jp/help/api)に従う。NDLへの取得は直列化し、キャッシュ・差分取得を使う。具体的な公開レート上限があるとは仮定しない。

紹介文・内容分類には、既存のWikipedia記事審査経路を用途と対象範囲が成立した分だけ再利用する。書誌が取れたことを紹介文・本文のAI入力許可へ転用しない。AniList・書店・出版社サイト等の追加経路は初期実装の必須依存にせず、上の二経路で不足した場合に限り再計画する。購入・有料API・禁止された取得に切り替えない。

**成果物:** 新しい作業領域`data/light-novels-v1/`に、候補ID・提供元・取得済み/未処理/保留、投入可能数、不足、用途条件と原資料hashを保存する。原資料とDB・個人履歴はGit対象外を維持する。

## 2. シリーズ・各巻・版を分け、魔法科の経路を先に通す

| 単位 | 保存・表示する内容 |
|---|---|
| 小説シリーズ | シリーズID、正式名・別題・読み、著者、原言語、種別の根拠、出典 |
| 各巻の原作品 | 作品ID、固有題・巻番号、所属シリーズと順序、その対応根拠 |
| 版・翻訳 | 出版社、刊行年、ISBN、言語、翻訳者、元の巻との関係 |
| 関係 | 続編・外伝・Web版/書籍版・メディア化を別種別で保存。不明な対応は保留 |

QIDがないNDLレコードにも出典付きの内部IDを付ける。現行APIのQIDだけを受け付ける契約は、種別を持つ参照を追加する新しい契約で拡張し、既存のQID・URL・読書履歴を引き続き扱えるようにする。新しいシリーズ用テーブル・索引・分類契約は追加形式で実装し、既存の単巻用取込み条件や固定証跡を緩めない。

シリーズ所属・版統合は、明示された関係、提供元の識別子、著者・巻表示・出版情報等を照合し、参照箇所を保存する。タイトルだけ、タイトルと著者だけ、ISBNだけで原作品の同一性を確定しない。ISBNは版の識別に用いる。NDLのシリーズ欄が出版レーベルや叢書を指す場合もあるため、そのまま物語シリーズIDへ変換しない。各巻の原作品対応が未確定でも、版としての検索表示とシリーズの利用は独立して進める。

まず魔法科と、根拠のある比較候補を少数取り込み、検索→詳細→好きな作品→推薦までの最小の経路を完成させる。公式名・部分一致・保存済み別題・読みの検索を扱い、Unicode・空白・全半角の正規化は検索キーに限定して原題を保持する。曖昧な略称や同名作品を自動統合しない。

**完了条件:** ローカルサーバーの実HTTPと画面で魔法科を小説シリーズとして検索でき、シリーズ表示と出典を確認できること。好きな作品から少なくとも1件の別の小説作品/シリーズを理由・出典付きで推薦できること。アニメ・漫画の混入、指定シリーズ自身や版違いによる推薦の重複がないこと。使える特徴がなければ不足を表示し、この完了条件は未達として扱う。

## 3. 100シリーズで検索・分類・推薦を成立させる

最初の検証対象はCodex側で選び、本人への作品リスト提出や採点を依頼しない。魔法科を必須に、ソードアート・オンライン、Re:ゼロから始める異世界生活、涼宮ハルヒ、とある魔術の禁書目録、転生したらスライムだった件などを選定候補とする。採用する正式名・単位・対応は取得した一次書誌等で確認する。複数レーベル・年代と、漫画/アニメ化・続編・外伝・版違いの混同例を含む固定20シリーズの照合表を作る。

内容分類は資料が扱う単位に固定する。シリーズの記事から得た特徴を、各巻の特徴や既存の単巻分類へコピーしない。シリーズのジャンル・テーマ・構造・主人公・雰囲気に、根拠・関連度・未校正の確信度を付けて別審査する。本文根拠のない文体は不明とする。書誌しかない作品は検索と根拠のある書誌ジャンル推薦へ先に接続し、詳細分類済みとは表示しない。

Sol CLIは既存の4/8並列制御・最大8並列を再利用し、分類は1対象/呼出し、別審査は最大5対象/呼出しとする。シリーズに対応した入力・出力契約を先に限定検証し、失敗率5%以下・表示特徴採用率70%以上の条件を維持する。取得準備と分類・審査は独立する範囲で並行し、DB書込みは一系統とする。

推薦ではシリーズを「好きな作品」に指定でき、書誌ジャンルのみと内容根拠付き特徴を区別して理由を表示する。シリーズの推薦と各巻への案内を区別し、同じシリーズの巻や版で候補一覧を埋めない。シリーズの既読状態と各巻の状態は分け、1巻の既読から全巻既読を推定しない。新しいシリーズを探す推薦では、好きなシリーズと既読関係が確定した同一シリーズをまとめて除外し、続巻の案内は別扱いとする。不明を未読と表示しない。

**移行条件:** 検索可能な異なる100シリーズ、固定20シリーズの検索・種別・対応確認20/20、内容特徴を採用した50シリーズ以上を目標とする。魔法科の通し確認と代表的な別シリーズでの推薦が成功し、採用・保留・重複の内訳を報告できること。供給不足や条件未達なら達成扱いにせず、成立済みの検索・推薦機能は提供する。この確認は接続・回帰の検証であり、独立した分類精度や推薦満足度ではない。

## 4. 1,000シリーズへ拡張し、日本語ライトノベルを常設する

100シリーズの実測を使って、検索可能1,000シリーズ・内容特徴あり500シリーズ以上を次の目標にする。各巻と版の件数は供給実績を別集計し、巻数でシリーズ数を水増ししない。レーベル・年代・ジャンル別の不足を補い、新刊だけ・特定レーベルだけに偏った場合は明示する。目標値は取得・採用済み件数の保証ではなく、実際に条件を満たした到達数を報告する。

検索画面にライトノベルと小説シリーズの区分を設け、日本語名での検索、別題・著者検索、シリーズ詳細と収録巻、好きな作品による推薦を常設する。元の世界小説の検索・推薦も維持する。NDLだけにある巻、書誌のみ、内容特徴あり、未対応の版関係を表示上区別する。推薦理由に資料と分類対象の範囲を示し、シリーズ全体を読了・評価したと推定しない。

**完了条件:** 上記目標の実数、魔法科を含む固定検索例、シリーズ/巻/版の非重複、元の20,000分類と履歴の保持、追加分の監査と推薦画面を確認して結果文書を残す。実装の関連試験と確定した実装のUbuntu・Windows Python 3.14 CIを確認し、公開差分を点検してコミット・push・PR反映へ進む。個人データは公開しない。

## 5. ライトノベルの利用を保ち、世界小説の拡張へ戻る

1,000シリーズまでの供給量・採用率・不足と処理時間から、3,000シリーズ以上への拡張を判断する。世界小説の詳細分類3万→5万→10万作品以上という長期目標も維持し、新規に確定した各巻の作品だけを該当する作品数へ計上する。シリーズ分類数は別指標とし、「シリーズ込みで単巻詳細分類3万達成」とは報告しない。

既存335評価は、新しく確実な作品/シリーズ対応が得られた対象だけ照合する。巻の評価をシリーズ全体へ自動転記せず、評価単位・母数と作品/シリーズ/著者の漏洩を確認する。比較母数がなければ本人向け改善は評価不能のままとし、追加の本人評価を要求しない。独立評価の未成立を、根拠が成立した作品の利用・拡張を止める条件にはしない。

ToC提供は[既存の候補表](toc-candidate-v1.md)を土台に、追加した提供元・コード・分類対象・用途条件・履歴の扱いを更新する。書誌、紹介文、画像、全文の許諾を混同せず、AI入力・表示・再配布・商用を用途別に管理する。無料で取得できることだけから一般公開・商用提供まで許可済みとは扱わない。

## 進め方と不要な反復の防止

今回の計画更新では、収集・分類・移行・サーバー再起動・全件pytestを実行しない。次の実行は魔法科の経路の完成を最優先とし、全1,000シリーズや全巻の収集完了を待って画面へ反映する進め方にしない。既存[PR #30](https://github.com/ayutaz/recommend-book/pull/30)の2万分類版の反映は別の区切りとして扱い、シリーズ追加の設計・準備を待たせない。

関連する契約・検索・推薦・既読除外・版の混同・既存QIDの互換性を合成fixtureで検証し、各段階の実HTTP・画面確認は必要な条件を一度ずつ行う。保存済みの2万分類の全件再分類・同じ監査・335評価の全件再照合・並列数の再実験を挟まない。APIや用途条件が変わった場合、失敗・不具合や資料の不足が判明した場合だけ、関係する工程を追加する。

完了時刻は、魔法科の通し確認と100シリーズの実際の供給・採用・処理時間から見積もる。既存2万分類の所要時間から、新しいシリーズ処理の時間を保証しない。通常の実装・取得・検証・Git反映はCodexが判断し、無料で成立しない項目は不足として記録して、成立している系統を続ける。
