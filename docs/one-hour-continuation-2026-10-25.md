# ライトノベル対応を進める1時間の実行計画

作成: 2026-10-25。既存v25計画の続き。通常の判断は担当側で行い、確認待ちを作らず実行する。ユーザーの指示により、利用可能な4系統で並列に進める。

## 現在地

既存進捗の確認値は100,620 entry、独立掲載参照9,870、物語シリーズ2,197、内容特徴572。未commitの計画・進捗文書2件は保持する。次の優先対象は保存済みIris資料の未接続差分である。保存年別資料と特集資料は同一範囲として扱わない。

## 時間配分と担当

| 開始から | 主担当 | 作業と成果物 |
|---|---|---|
| 0〜10分 | 全担当 | 既存記録・保存資料・実装契約を確認。対象と編集箇所を分離 |
| 10〜35分 | 差分担当 | Irisの既対応・題検索候補・未検索をread-only DBと保存metadataで分離し、対象IDと根拠をJSONへ保存 |
| 10〜35分 | 実装担当 | 年別Irisの選択範囲認証と独立掲載参照を実装し、対象試験を実行。特集の漫画等を一括で小説と認定しない |
| 10〜35分 | 性能担当 | 検索・詳細の遅延を有限な計測で調べ、出典認証を保った改善と回帰確認を実施 |
| 10〜40分 | 統合担当 | 選択資料・実装を固定した取込み手順を準備。DB書込みは一系統とし、旧ID・SHA・所属・分類・読書状態の保持を確認 |
| 35〜50分 | 統合担当と各担当 | 確定実装の関連試験、代表の実HTTP確認、可能な範囲の画面確認。失敗は原因修正後に必要な部分だけ再実行 |
| 50〜60分 | 統合担当 | 実採用件数・保留・所要時間を記録。可能な権限内でcommit・push・PR反映し、実装区間のCIを1回確認 |

各工程は時間枠で打ち切り、完了・未着手・実行中・失敗を区別する。CI未完了や代表確認を全件成功と扱わない。取込み条件が整わない場合は、検証済み実装と差分一覧を成果として残し、未検証のDB採用はしない。

## 利用枠の扱い

ユーザーはサブスク枠を1時間で最大限活用することを希望している。既存サブスク接続内で、独立した実作業を最大4系統に分担する。10bを100億tokensと解釈すると必要速度は約278万tokens/秒であり、この環境の実行量として達成を約束しない。実残量とリセット時刻は本セッションから未確認で、token数をサブスク残量へ換算しない。

既存100作品の分類・別審査は約35.8分、入力3,244,599・出力194,663 tokensの記録がある。現行ライトノベルの直近分類試行は採用基準未達で停止しており、同一入力の再分類による消費は行わない。新しい内容根拠と用途条件が確認できた入力だけを次の分類候補とする。有料API・購入への切替はしない。

公式資料ではサブスク使用量はモデル、文脈、推論、ツール、検索、キャッシュ等に左右される。[OpenAI公式の利用枠説明](https://learn.chatgpt.com/docs/pricing?codex-pricing-plans=individual)。

## 実行上の制約

ユーザーは承認を求めないよう指示している。環境側の実行承認を担当側から無効化できないため、許可済み操作を優先し、追加承認が必要な操作は避けて他の作業を進める。特権実行の承認要求は出さない。

データ・原資料・個人履歴はGit対象外のdataへ保存する。書誌参照を同一版・物語シリーズ・内容推薦へ自動昇格しない。旧資料全件の再取得・再監査・再分類をせず、変更範囲に応じて検証する。


## 実行結果

Iris年別51・特集15参照を採用し、100,686 entryへ更新した。旧データ保持と実HTTP検索・代表詳細を確認した。一般書誌詳細の単発比較は33.627→17.188秒で、返却内容のSHAは一致。関連701試験と特集14試験が成功。原資料・DB・履歴はGitへ含めない。両OS CIとPR反映は進捗へ追記する。

権限変更前に作成した子担当から承認が続いたため、子担当の実行を停止し、親環境内の並列コマンドへ集約した。これを解消するまで実作業が遅れた。担当再利用だけで権限更新が反映されると仮定しない。
