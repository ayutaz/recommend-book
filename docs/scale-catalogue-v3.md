# 10万作品への拡張と好み指定の推薦

更新: 2026-10-21。[計画v19](autonomous-next-phase-plan-v19.md)の1〜3を実行中。開始時は検索可能32,126作品、資料ジャンル付き24,741作品、詳細分類5,000作品、表示特徴あり4,658作品だった。[前段階の完了結果](scale-catalogue-v2.md)は変更しない。

## 今回の到達条件

- 検索可能100,000作品以上。取得済みの分から順次検索へ追加する。
- 好きな作品・重視する特徴・避けたい特徴・軸の重みで候補を選べ、理由と出典を確認できる。
- 既存5,000作品を保持し、詳細分類を累計10,000作品へ増やす。

書誌・推薦・内容資料と分類を並行する。追加費用・外注・本人の追加評価は前提にしない。1〜3全体の完了、10万作品での性能、本人向け精度改善を達成済みとは扱わない。

## 先行実装した推薦機能

検索結果から複数の作品を基準に選び、テーマ・物語構造・主人公・雰囲気の重視と回避、軸の重み、ジャンル・原言語・年代を指定できる。基準に選んだ作品と既読作品を候補から除き、根拠が不足する作品には書誌情報による経路を残す。読書状態の不明は未読と区別する。

順位は再現可能な計算式で決め、閲覧時のLLM呼出しはない。候補選定用の未認証ラベルを、そのまま推薦理由や確定スコアに使わない。実際に使う内容特徴は分類出力・入力・出典との結び付きを確認し、破損や保留があれば採用しない。同一著者と、原資料のP179で明示されたシリーズへの集中を抑える。題名からシリーズを推測しない。

画面には、指定した特徴との一致と基準作品との共通点、避けたい特徴への該当、未確認の軸、未校正スコアを表示する。内容分類には記事の版・寄稿者履歴・ライセンス・変更内容・出力の利用条件を表示する。モデル確信度や推薦スコアを好みの的中確率として扱わない。

## 確認した範囲

関連するバックエンド・HTTP fixture試験に加え、実データを使うHTTPとChromeで複数基準作品、重視/回避の排他切替、重み変更、候補30件、理由、特徴不足、出典と利用条件を確認した。動作確認用の選択は本人の嗜好・評価データとして保存せず、実台帳の読書状態も変更していない。

実データで日本語作品に絞ったHTTP推薦は各1回の観測で約0.37秒だった。担当のバックエンド測定では、好み未指定約0.14秒、テーマ指定で根拠を認証した3候補の取得約8.3秒だった。条件・実行方法が異なり、中央値や負荷試験ではない。10万作品・1万分類での最終測定は残っている。

既存統計処理を1回だけprofileし、全5,000分類の16,002ファイルに対する実バイト照合が主な待ち時間と分かった。検証を省略する変更は行わず、推薦では必要な候補の認証範囲を絞る。統計は引き続き一覧と別に読み込む。

## 書誌と分類の実行

新しい書誌取得処理は、旧取得ID・保留IDと現在の台帳を除外し、1,000件程度ずつ追記する。再開時の未処理ID、保存済みレコードの復元、重複反映、共有書込みロックを確認する。APIが指定した待機時間を守り、同じ失敗ページを再送しない。

従来の検索サービスの障害を受け、公開QLever検索を候補IDの発見に使う経路を追加した。書誌情報・作品種別・用途条件はWikidataの実エンティティと従来の検証から確認する。同じ条件の候補は1回の集計で136,765件だったが、重複や不適合を除く前の件数である。最初の1,000レコードから839作品を追加し、うち1作品が稼働中の検索・詳細HTTPへ反映されることを確認した。新規取得では言語フィルタを外し、従来の13言語外の実ラベルも保持する。過去の保留作品は再取得しない。

内容分類は既存の実行環境と許可確認を再利用する。新段階では1作品/呼出しで始め、別作品の入力hashや根拠を取り違えるリスクと、同じバッチの他作品を巻き込む保留を減らす。既存の失敗率5%以下・表示採用70%以上の条件を維持し、真正な実行・別審査・利用条件確認を通った新規作品だけを累計へ加える。

初回100作品は、76作品の実出力を得た時点で既存設定の200万トークン上限に達し、24作品を未処理で停止した。実行失敗0件だが、別審査・台帳反映は0件であり、累計5,000作品には加算しない。停止manifestと原出力は変更せず、新しい実行設定では分類と別審査の利用量に合う上限を用意する。同じ入力の再送や、停止結果を完了とする書換えは行わない。

入力資料・分類・台帳の同定確認と、独立正解に基づく精度検証は別である。文体は本文の根拠がない限り不明とし、既存335評価の全件再照合や同じ入力の再分類は繰り返さない。

## 残る作業とローカル記録

10万作品への取得・反映、新規5,000作品の分類・反映、拡張後の実データ監査と性能確認、確定コミットのUbuntu・Windows CI、mainへの反映が残る。今回の先行実装だけで1〜3全体を完了とはしない。

### ここからの実行順序

2026-10-21の台帳を読み取り確認した時点で、検索可能32,126作品、詳細分類5,000作品。残りは検索対象67,874作品以上と、新規分類5,000作品である。取得候補・準備済み資料・実行中の分類は、この反映済み件数に加えない。計画v19の目標・完了条件は維持する。

1. **書誌拡張を継続する。** 従来の検索サービスは、保存済み応答で障害による制限と確認した。同じ要求を繰り返さず、稼働を開始した公開QLever検索から候補IDを集める。候補の書誌はWikidataの実エンティティを取得し、従来と同じ小説・作品・用途条件を通ったものだけ、処理済み単位で検索DBへ追記する。5万件を中間点、10万件以上を完了条件とする。候補の大半が既存作品の場合は保存済みの重複率を見て探索範囲を調整し、重複取得を増やさない。
2. **分類資料の供給と新規分類を並行する。** 内容資料の取得は100窓を完了し、初期在庫383作品と新規5,922作品を合わせて6,305作品分を確保した。試行済み・保留作品は新規入力から除外する。追加取得を止め、後続資料の作品順・実行名・引渡し記録を一致させて接続する。初回停止の原因となった実行上限を新設定で修正し、未処理の異なる作品から分類を再開する。分類・別審査・失敗率・表示採用率の継続条件を満たせば、最大8並列で累計1万作品まで進める。既存5,000作品や失敗した同一入力を一括再実行しない。
3. **増えたデータを推薦へ反映する。** 好み指定の機能は先行実装済みなので、データ拡張のたびに画面を作り直さない。新しい書誌と採用済み分類を検索・候補生成へ反映し、10万作品・1万分類の段階で実HTTP・実画面の動作と待ち時間を測る。遅い箇所が実測された場合だけ改善する。分類待ちの作品も、成立する書誌条件で検索・推薦に利用する。
4. **検証とGit反映を完了する。** 実装の区切りで関連試験を行い、コミット・pushする。目標到達後に既存データ保持、重複、用途条件、採用・保留・不明の内訳を差分確認し、READMEと結果を更新する。確定コミットのUbuntu・Windows CIを通し、許可済みの範囲でPRをマージしてmainとの一致を確認する。同じコードへの全試験やCIは繰り返さない。

この1〜4を終えた後、既存評価と確実に結び付いた範囲で推薦比較を行い、無料運用・表示と再配布の条件・履歴の保存と削除を整理してToC候補へ進む。本人の追加評価は求めず、評価母数が不足する項目は未評価と明記する。独立した精度評価の不足を理由に、成立している書誌拡張や利用機能を停止しない。

実データと証跡はGit対象外の `data/autonomous-next-v3/scale-100000-v1/` に保存する。
